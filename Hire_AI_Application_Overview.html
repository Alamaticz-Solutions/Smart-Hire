Section 1
What is Hire AI?

Hire AI is an intelligent, AI-powered Recruitment Management System built for Alamaticz Solutions. It is a full-stack web application that automates the complete end-to-end hiring workflow — from the moment a candidate sends a resume by email, to the final selection stage — without any manual data entry or repetitive HR work.

It combines a modern React web interface with a powerful Python FastAPI backend, a large language model running on Groq Cloud (LLaMA 3.1), two relational databases (SQLite / PostgreSQL), and a vector database (ChromaDB) — all working together to deliver an intelligent recruitment assistant that works 24 hours a day, 7 days a week.

💡

In simple words: Imagine hiring 3–4 extra HR staff who work round the clock, never make data-entry mistakes, can search thousands of resumes in seconds, and automatically reply to applicants — all without any salary. That is what Hire AI does for your team.

Core Capabilities at a Glance

  • 📧 Auto Email Ingestion — Reads Gmail inbox every 30 seconds, extracts attached resumes (PDF/DOCX), and processes them automatically
  • 🧠 AI Resume Parsing — Extracts 25+ candidate fields (name, skills, CTC, experience, location, certifications) from any resume format
  • 💼 Job Description Management — Create, manage, and match job descriptions to a pool of thousands of candidates
  • 💬 AI Recruiter Chat — Ask questions in plain English like "Show me Pega candidates with 5+ years near Bangalore"
  • 📤 Bulk Import — Upload an Excel sheet and ingest hundreds of candidates in one click
  • 📄 Resume Generator — Auto-generate formatted A4 company-branded resumes from raw data
  • 🔐 Role-Based Access — Admins, HR, Recruiters, and External Clients each see only what they need
  • 📊 Reports & Export — One-click Excel export with built-in dropdown status validations

Section 3
How the Application Works — Data Flow

Here is the step-by-step journey of data through Hire AI, from a candidate sending a resume by email to a recruiter finding and evaluating that candidate:

1
📧 Candidate Sends Email with Resume A candidate emails their resume (PDF or DOCX) to the company Gmail inbox. The background email worker polls Gmail every 30 seconds via IMAP to detect new messages.
2
📎 Attachment & Duplicate Detection The system checks if this email's unique ID has already been processed (stored in the processed_emails table). If new, it downloads and saves the PDF/DOCX attachment to disk.
3
📖 Text Extraction (PyMuPDF / docx2txt) The resume file is converted to raw text. PyMuPDF handles PDF files; docx2txt handles Word files. The email body text is also extracted and combined.
4
🧠 AI Extraction via Groq LLaMA 3.1 The combined text is sent to the LLaMA 3.1 model on Groq Cloud with a detailed extraction prompt. The AI returns a structured JSON object with 25+ fields: full name, skills, CTC, experience, certifications, location, LinkedIn, phone, email, and more.
5
🗄️ Database Storage (SQLite / PostgreSQL) The extracted candidate data is saved as a new record in the candidate_metadata table. If the candidate already exists (detected by sender email or a reference ID in the subject line), the record is merged and updated instead.
6
📐 Vector Embedding (ChromaDB) The resume text is chunked into pieces, converted into 384-dimensional numerical vectors using the all-MiniLM-L6-v2 embedding model (running locally on CPU), and stored in ChromaDB for semantic search.
7
✅ Auto Job Matching The system immediately checks all active job descriptions and evaluates whether this candidate qualifies — using experience thresholds, certification matching (CSSA/CSA/LSA), and location preference alignment.
8
📮 Auto SMTP Reply to Candidate The system audits the extracted profile. If any required fields are missing (e.g., notice period, CTC, LinkedIn), it sends an automated email to the candidate requesting those details. If all fields are complete, it sends an acknowledgment of successful application receipt.
9
👩‍💼 Recruiter Reviews on Dashboard The recruiter opens the web application, sees the candidate in the dashboard table, can view the formatted resume, update status, match to more jobs, or chat with the AI to query the candidate database in plain English.

Chat Pipeline — 3 Smart Routes

When a recruiter types a question in the chat interface, the system intelligently routes it through one of three paths:

🗣️ Route 1 — Conversational

For greetings and general questions ("Hello", "Who are you?"). The LLM responds directly without touching the database.

🗃️ Route 2 — Structured SQL

For database questions ("Show me Pega candidates in Hyderabad with 5+ years"). The LLM converts this to SQL filter parameters, queries SQLite, and returns a formatted table.

🔍 Route 3 — RAG Vector Search

For free-form questions about resume content. ChromaDB finds the most semantically similar resume chunks; the LLM synthesizes a context-aware answer.

Section 5
AI Model & Intelligence Layer

Primary Model — Groq LLaMA 3.1 8B Instant

The main AI engine is Meta's LLaMA 3.1 (8 billion parameters) running on Groq's dedicated LPU hardware via API. Groq provides extremely fast inference (hundreds of tokens per second) compared to traditional GPU inference, making real-time resume parsing and chat responses near-instant.

Use Case in Hire AI How the AI is Used Output
Resume Parsing Raw PDF/email text → detailed extraction prompt Structured JSON with 25+ candidate fields
JD Document Parsing Uploaded PDF/DOCX job description → extraction prompt JSON that auto-fills the Create Job form
Candidate-Job Matching Candidate list + JD → evaluation prompt (25 at a time) Match/Reject decision + AI-written reason for each
Chat (Route 2) Natural language question → SQL parameter conversion Structured query parameters for SQLite
Chat (Route 3 — RAG) Vector search results (resume chunks) → synthesis prompt Natural language answer based on real resume content
Conversational Chat General greeting / info questions Direct conversational AI response

Embedding Model — Sentence Transformers (Local)

The model sentence-transformers/all-MiniLM-L6-v2 runs entirely locally on CPU (no cloud cost). It converts resume text into 384-dimensional numerical vectors that represent the semantic meaning of the text.

📐

What is a vector embedding? When you search "experienced Pega architect", the system doesn't just look for those exact words. It converts your query into a 384-number vector and finds resumes whose vectors are numerically closest — meaning it finds semantically similar content even if the exact words are different.

JD Matching — Batch Processing Strategy

Groq's free tier has a limit of approximately 6,000 tokens per minute (TPM). To handle large candidate pools without hitting this limit, the system automatically splits candidates into sequential batches of 25 and evaluates each batch with a short wait between requests. This ensures large-scale matching works reliably without API errors.

Section 6
Database Design

Hire AI uses a three-layer hybrid database strategy to handle structured data, cloud scale, and semantic search simultaneously:

🗂️
SQLite
Local Relational Database · stats.db

Embedded database file used in local development. Stores all structured candidate, job, user, and configuration data across 12 tables. Requires zero setup — works out of the box.

🐘
PostgreSQL
Cloud Relational Database · Production

Cloud-hosted production database for scale. The application dynamically switches to PostgreSQL if credentials are found in the environment variables — no code change needed.

🔍
ChromaDB
Vector Database · chroma_db/

Stores 384-dimensional vector embeddings of resume text chunks. Powers the RAG (Retrieval-Augmented Generation) pipeline for semantic, context-aware candidate search.

Section 7
Backend — FastAPI & Processing Engine

The entire backend is a single FastAPI application in backend/main.py (265 KB — one of the largest single-file backends you'll encounter). It exposes REST API endpoints that the frontend consumes via Axios HTTP calls.

Core Backend Modules

📧 Email Ingestion Worker (Background Thread)

  • Runs as a background daemon thread alongside the web server
  • Polls Gmail every 30 seconds using Python's built-in imaplib
  • Fetches the last 30 messages, checks each against processed_emails table
  • Extracts text from PDF (PyMuPDF) or DOCX (docx2txt) attachments
  • Calls Groq LLaMA 3.1 with the extraction prompt to get structured JSON
  • Detects existing candidates via Ref ID in subject line (regex: Ref: CAND-{id}) or sender email match
  • Merges updates into existing records or creates new ones
  • Sends auto SMTP reply via Gmail SMTP (missing fields request or acknowledgment)

🔄 Asynchronous File Processing

  • Resume uploads are processed in background tasks (FastAPI's BackgroundTasks) so the UI stays responsive
  • A thread lock (_processing_lock) prevents multiple heavy operations running simultaneously to avoid memory overload
  • Converts files → extracts text → calls Groq → writes to SQLite → indexes into ChromaDB → runs JD matching

📊 Excel Bulk Import

  • Accepts uploaded .xlsx files from recruiters
  • Maps column headers to candidate database fields
  • Detects and updates duplicates; creates new records for new entries
  • Automatically triggers JD matching for all newly ingested candidates

📄 JD Document Auto-Parser (/api/jobs/parse-document)

  • Recruiter uploads a PDF or DOCX job description file
  • Backend extracts text and sends to LLaMA 3.1 with a JD extraction prompt
  • Returns structured JSON matching the job form schema
  • Frontend uses this JSON to auto-fill all fields in the Create Job form

📄 Formatted Resume Generator (/api/candidates/{id}/resume-pdf)

  • Uses AI-cached formatted_json or calls Groq to regenerate it
  • Generates a two-column A4 HTML layout (left: Education/Certifications/Skills; right: Summary/Experience)
  • Uses a millimeter-based height engine to flow content correctly across multiple pages without blank page inserts

Frontend — React & UI Features

The frontend is a React 18 Single Page Application (SPA) bundled by Vite. It communicates with the FastAPI backend exclusively via Axios HTTP calls. The UI is styled with custom vanilla CSS (no Tailwind or Bootstrap) with light/dark theme support.

Application Pages

Page Route Accessible To Key Features
Login / Register /login Everyone Firebase Auth or native DB login, password validation, register with approval flow
Dashboard / All logged-in Candidate table, filter/search, status updates, formatted resume preview, Excel export
Jobs /jobs HR, Admin, External Create/edit JDs, AI matching, candidate selection, client sharing, JD document upload
Upload /upload Recruiter+ Drag-drop PDF/DOCX upload, Excel bulk import, real-time processing status
Chat /chat Recruiter+ AI chatbot with 3 routing modes, markdown rendering, candidate result cards

Notable UI Features

  • Light / Dark Theme — Toggle stored in localStorage, applied via CSS custom properties on document.documentElement
  • Recruiter Persona Matrix — Switch active recruiter persona (Boopathi, Praveen, Harish, Sabari) from the header; all API calls use the selected persona via the x-user-username header
  • Data Masking — Sensitive fields (CTC, certifications) shown as [HIDDEN] for non-HR users; keywords like CSSA/LSA replaced with **** based on the masked_keywords table
  • Excel Export with Dropdowns — Exported Excel sheets have built-in cell validation dropdowns (New / In-Review / Available / etc.) so clients can update candidate statuses directly in Excel
  • Drag-and-Drop Upload — Powered by react-dropzone; accepts PDF, DOCX, and XLSX file types
  • Recharts Metrics — Dashboard shows recruitment statistics as charts (candidates by status, experience distribution, etc.)
  • React Markdown — Chat responses from the AI are rendered as rich markdown with tables, bullet points, and formatted text

Section 10
Security & Access Control

Hire AI implements a 4-level role-based access control (RBAC) system:

Role Can See Can Do Hidden From Them
Admin Everything User management, approve requests, custom fields, keyword masking, email settings, all candidate data Nothing
HR All candidate fields except admin settings View/edit candidates, create jobs, run matching, export data User management, system settings
Recruiter Candidate data with masking applied Upload resumes, search candidates, chat AI, view jobs CTC/salary data, certification details (masked to ****)
External Client Only jobs shared with them + matched candidates View shared job postings and matched candidate profiles only All CTC/salary, contact details, full candidate database

Additional Security Features

  • Per-User Field Hiding — Admin configures which fields each user cannot see (stored in users.hidden_fields as comma-separated column names)
  • Keyword Masking Table — Words in the masked_keywords table are replaced with **** for non-admin/non-HR users throughout the UI
  • Change Request Workflow — Profile edits by non-admins create a pending change_request that an admin must approve before changes apply
  • Activity Log — Every login, upload, status change, and admin action is recorded in activity_logs with username and timestamp
  • Account Approval — New user registrations remain in is_approved = 0 state until an admin approves them
  • Firebase Auth (Optional) — Can optionally sync with Firebase for Google OAuth-based authentication
