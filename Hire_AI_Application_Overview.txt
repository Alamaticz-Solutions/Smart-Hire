   1. WHAT IS HIRE AI?
   ------------------------------------------------------------------------

   Hire AI is an AI-powered Recruitment Management System built for Alamaticz
   Solutions. It is a full-stack web application that automates the complete
   end-to-end hiring workflow — from the moment a candidate sends a resume
   by email, to the final selection stage — without any manual data entry
   or repetitive HR work.

   It combines a modern React web interface with a powerful Python FastAPI
   backend, a large language model running on Groq Cloud (LLaMA 3.1), two
   relational databases (SQLite / PostgreSQL), and a vector database
   (ChromaDB) — all working together to deliver an intelligent recruitment
   assistant that works 24 hours a day, 7 days a week.

   In simple words: Imagine hiring 3 to 4 extra HR staff who work round the
   clock, never make data-entry mistakes, can search thousands of resumes in
   seconds, and automatically reply to applicants — all without any salary.
   That is what Hire AI does for your team.

   Core capabilities:

      - Auto Email Ingestion: Reads Gmail inbox every 30 seconds, extracts
      attached resumes (PDF/DOCX), and processes them automatically.

      - AI Resume Parsing: Extracts 25+ candidate fields (name, skills, CTC,
      experience, location, certifications) from any resume format.

      - Job Description Management: Create, manage, and match job descriptions
      to a pool of thousands of candidates.

      - AI Recruiter Chat: Ask questions in plain English like "Show me Pega
      candidates with 5+ years near Bangalore."

      - Bulk Import: Upload an Excel sheet and ingest hundreds of candidates
      in one click.

      - Resume Generator: Auto-generate formatted A4 company-branded resumes
      from raw candidate data.

      - Role-Based Access: Admins, HR, Recruiters, and External Clients each
      see only what they are permitted to see.

      - Reports and Export: One-click Excel export with built-in dropdown
      status validations.

   3. HOW THE APPLICATION WORKS — STEP BY STEP
   ------------------------------------------------------------------------

   Step 1: Candidate Sends Email with Resume
      A candidate emails their resume (PDF or DOCX) to the company Gmail
      inbox. The background email worker polls Gmail every 30 seconds via
      IMAP to detect new messages automatically.

   Step 2: Attachment Detection and Duplicate Check
      The system checks if this email's unique ID has already been processed
      (stored in the processed_emails table). If it is a new email, it
      downloads and saves the PDF or DOCX attachment to disk.

   Step 3: Text Extraction
      The resume file is converted to raw text. PyMuPDF handles PDF files.
      Docx2txt handles Word files. The email body text is also extracted
      and combined with the resume text.

   Step 4: AI Extraction via Groq LLaMA 3.1
      The combined text is sent to the LLaMA 3.1 model on Groq Cloud with
      a detailed extraction prompt. The AI returns a structured data object
      with 25+ fields including full name, skills, current CTC, expected CTC,
      total experience, Pega experience, CDH experience, certifications,
      current location, preferred locations, LinkedIn, phone, email, and more.

   Step 5: Database Storage
      The extracted candidate data is saved as a new record in the
      candidate_metadata table. If the candidate already exists (detected
      by matching the sender email or a reference ID like "Ref: CAND-42"
      in the subject line), the existing record is merged and updated instead
      of creating a duplicate.

   Step 6: Vector Embedding for Semantic Search
      The resume text is chunked into pieces and converted into 384-dimensional
      numerical vectors using the all-MiniLM-L6-v2 embedding model (running
      locally on CPU). These vectors are stored in ChromaDB for semantic search.

   Step 7: Automatic Job Matching
      The system immediately checks all active job descriptions and evaluates
      whether this new candidate qualifies — using experience thresholds,
      certification matching (CSSA/CSA/LSA equivalences), and location
      preference alignment.

   Step 8: Auto Reply to Candidate
      The system checks the extracted profile for missing required fields.
      If any fields are missing (notice period, CTC, LinkedIn, etc.), it sends
      an automated SMTP email to the candidate requesting those details. If
      everything is complete, it sends an acknowledgment confirming receipt
      of the application.

   Step 9: Recruiter Reviews on Dashboard
      The recruiter opens the web application, sees the new candidate in the
      dashboard table, can view the formatted resume, update the status, match
      to more jobs, or use the AI chat to query candidates in plain English.

   CHAT PIPELINE — 3 ROUTES:
      When a recruiter types a question in the chat, the system routes it:

      Route 1 (Conversational): For greetings and general questions.
      The AI responds directly without touching the database.

      Route 2 (Structured SQL): For database questions like "Show me Pega
      candidates in Hyderabad with 5+ years." The AI converts the question
      into SQL filter parameters, queries the database, and returns a table.

      Route 3 (RAG Vector Search): For free-form content questions.
      ChromaDB finds the most semantically similar resume chunks. The AI
      synthesizes a natural language answer from that content.


   ------------------------------------------------------------------------
   4. SYSTEM ARCHITECTURE
   ------------------------------------------------------------------------

   Hire AI consists of five interconnected layers:

   LAYER 1 — USER INTERFACE
      React 18 + Vite frontend (Port 5173 in development / served by
      backend in production). Contains 8 pages: Dashboard, Jobs, Upload,
      Chat, Admin, Login, Connect, Templates.

   LAYER 2 — API SERVER
      FastAPI + Uvicorn running on Port 8000. Exposes REST API endpoints
      that the frontend calls via Axios HTTP requests.

   LAYER 3 — DATA STORAGE
      SQLite (local) or PostgreSQL (cloud) for structured relational data.
      ChromaDB for vector embeddings used in semantic search.

   LAYER 4 — AI ENGINE
      Groq Cloud (LLaMA 3.1 8B Instant) for text understanding, extraction,
      matching, and conversation. Sentence Transformers (all-MiniLM-L6-v2)
      running locally for vector embedding generation.

   LAYER 5 — EMAIL INTEGRATION
      Gmail IMAP background worker thread polling every 30 seconds. Gmail
      SMTP for sending automated acknowledgment and missing-field request
      emails to candidates.

   RUN MODES:
      Production mode: Frontend is built into static files and served by
      FastAPI on a single port (8000). One process, one URL.

      Development mode: Vite dev server runs on port 5173 with hot reload.
      FastAPI runs separately on port 8000. Allows instant UI changes
      without rebuilding.


   ------------------------------------------------------------------------
   5. AI MODEL AND INTELLIGENCE LAYER
   ------------------------------------------------------------------------

   PRIMARY MODEL: Groq LLaMA 3.1 8B Instant
      - Model: llama-3.1-8b-instant
      - Provider: Groq Cloud API
      - Parameters: 8 billion
      - Speed: Hundreds of tokens per second (Groq's dedicated LPU hardware
      is significantly faster than traditional GPU inference)

   What LLaMA 3.1 does in Hire AI:

      a) Resume Parsing
         Reads raw text extracted from PDF or DOCX resumes and returns a
         structured JSON object with all candidate fields filled in.

      b) Job Description Parsing
         Reads an uploaded PDF or Word JD file and returns structured JSON
         that auto-fills the Create Job form in the UI.

      c) Candidate-Job Matching
         Evaluates a list of candidates against a job description and
         returns a match or reject decision with an AI-written reason for
         each candidate. Processed in batches of 25 due to rate limits.

      d) Chat (Route 2 — Structured)
         Converts a recruiter's natural language question into SQL filter
         parameters (e.g., min_pega_exp: 5, location: Hyderabad).

      e) Chat (Route 3 — RAG)
         Takes resume chunks retrieved from ChromaDB and synthesizes a
         coherent natural language answer to the recruiter's question.

      f) General Conversation
         Handles greetings, identity questions, and general recruitment
         guidance as a conversational AI assistant.

   EMBEDDING MODEL: Sentence Transformers (all-MiniLM-L6-v2)
      - Runs entirely locally on CPU (no cloud cost)
      - Converts text into 384-dimensional numerical vectors
      - Powers semantic search in ChromaDB
      - Used for both storing resume embeddings and querying at search time

   RATE LIMIT HANDLING:
      Groq's free tier allows approximately 6,000 tokens per minute. To
      handle large candidate pools, the matching engine processes candidates
      in sequential batches of 25 with automatic wait intervals between
      batches to prevent API errors.

   CERTIFICATION INTELLIGENCE:
      The AI automatically understands and maps Pega certification
      equivalences:
      - CSA  = PEGA Certified System Architect (Entry level)
      - CSSA = PEGA Certified Senior System Architect (Mid level)
      - LSA  = PEGA Certified Lead System Architect (Senior level)


   ------------------------------------------------------------------------
   6. DATABASE DESIGN
   ------------------------------------------------------------------------

   Hire AI uses three databases working together:

   DATABASE 1: SQLite (stats.db)
      A local embedded database file. Used in development and on any machine
      without PostgreSQL setup. Requires no installation — works out of the
      box. Contains all 12 structured tables.

   DATABASE 2: PostgreSQL (Cloud)
      A cloud-hosted relational database for production scale. The application
      automatically detects PostgreSQL credentials in the environment and
      switches from SQLite to PostgreSQL dynamically without any code change.

   DATABASE 3: ChromaDB (Vector Database)
      Stores 384-dimensional vector embeddings of resume text chunks. Enables
      semantic similarity search — finding resumes that are contextually
      similar to a search query even if the exact words don't match. Stored
      locally in the chroma_db folder.

   THE 12 DATABASE TABLES:

   Table 1: candidate_metadata
      The main candidate profile table. Stores all information about each
      candidate including full name, filename, status, total experience,
      Pega experience, CDH experience, skills, certifications, current CTC,
      expected CTC, percentage hike, notice period, availability in days,
      current organization, current client, email, phone, LinkedIn, current
      location, preferred locations, domain, tier, certification version,
      email message body, formatted resume JSON cache, sender email,
      qualification flag, approval flag, created by, and timestamp.

   Table 2: jobs
      Stores all job descriptions posted by recruiters. Fields include job
      title, description, client name, contact name, client phone, account
      manager, assigned recruiter, target date, job type, job status, work
      experience required, industry, salary, and required skills.

   Table 3: job_candidates
      The mapping table connecting candidates to jobs. Stores the job ID,
      candidate ID, AI-generated reason for the match or rejection, and
      the current status (matched or selected).

   Table 4: users
      Recruiter, HR, Admin, and External Client accounts. Stores username,
      password, email, role, HR flag, admin flag, external flag, hidden
      fields configuration, and approval status.

   Table 5: custom_columns
      Tracks dynamic custom fields added by admins to the candidate database.
      Each record has a key name, display label, and description that tells
      the AI what to extract for this field from future resumes.

   Table 6: change_requests
      Audit log for pending profile changes submitted by non-admin users.
      Each request stores the submitter, action type, target ID, proposed
      changes as JSON, description, status (pending/approved/rejected), and
      timestamp.

   Table 7: activity_logs
      System-wide audit trail. Records every login, upload, status change,
      and admin action with the username and timestamp.

   Table 8: team_members
      A simple dictionary of recruiter persona names used in the recruiter
      matrix feature (e.g., Boopathi, Praveen, Harish, Sabari).

   Table 9: job_shares
      Stores which external client users have been given access to view
      a specific job posting and its matched candidates.

   Table 10: masked_keywords
      A list of keywords (like CSSA or LSA) that are automatically replaced
      with **** for any user who is not an Admin or HR. Prevents sensitive
      certification information from being visible to external parties.

   Table 11: integrations_settings
      Stores the Gmail integration configuration including email address,
      password or app password, IMAP host and port, SMTP host and port,
      trigger keywords, and enable/disable flags.

   Table 12: processed_emails
      Stores the unique message ID of every email that has been processed.
      This prevents the same resume from being imported twice if the worker
      reads the same email on a subsequent poll cycle.


   ------------------------------------------------------------------------
   7. BACKEND — FASTAPI AND PROCESSING ENGINE
   ------------------------------------------------------------------------

   The backend is built on FastAPI, a modern Python web framework, and runs
   on Uvicorn as the ASGI server. The entire backend logic is in one file:
   backend/main.py (265 KB). It exposes REST API endpoints consumed by the
   frontend via Axios HTTP calls.

   MAIN BACKEND MODULES:

   a) Email Ingestion Worker
      Runs as a background daemon thread alongside the web server. Connects
      to Gmail every 30 seconds using Python's built-in imaplib. Fetches
      the last 30 messages, checks each against the processed_emails table,
      downloads new attachments, extracts text, calls Groq LLaMA 3.1 for
      extraction, detects existing candidates via Ref ID or sender email,
      merges or creates records, then sends an auto SMTP reply.

   b) Asynchronous File Processing
      Resume uploads are processed using FastAPI's BackgroundTasks so the
      UI stays responsive while heavy processing happens in the background.
      A thread lock prevents multiple heavy operations from running at the
      same time to avoid memory overload.

   c) JD Matching Logic (match_candidates_for_job)
      Evaluates candidates against a job description using LLaMA 3.1.
      Processes candidates in sequential batches of 25 to respect Groq's
      rate limits. Applies three matching criteria:
      1. Experience: candidate experience must be >= required years in JD
      2. Certifications: CSSA/CSA/LSA acronym equivalences automatically
         resolved
      3. Location: candidate's current location or any preferred location
         must align with the job location

   d) Excel Bulk Import
      Accepts uploaded .xlsx files. Maps column headers to candidate fields.
      Creates new records for new candidates. Updates existing records for
      duplicates. Triggers JD matching for all newly ingested candidates.

   e) JD Document Auto-Parser
      Endpoint: /api/jobs/parse-document
      Recruiter uploads a PDF or DOCX job description. Backend extracts
      text and sends to LLaMA 3.1 with a JD extraction prompt. Returns
      structured JSON that auto-fills all fields in the Create Job form.

   f) Formatted Resume Generator
      Generates a two-column A4 HTML layout. Left panel contains education,
      certifications, technical skills, and recognitions. Right panel
      contains profile summary, domain skills, and work experience. Uses
      a millimeter-based height calculation engine to flow content correctly
      across pages without blank page inserts or content cutoff.

   KEY API ENDPOINTS:
      GET  /api/candidates              — List candidates with filters
      POST /api/upload-resume           — Upload single PDF/DOCX resume
      POST /api/upload-excel            — Bulk import from Excel
      POST /api/chat                    — AI recruiter chatbot
      POST /api/jobs                    — Create new job description
      POST /api/jobs/{id}/match         — AI match candidates to a job
      POST /api/jobs/parse-document     — Parse JD doc, auto-fill form
      GET  /api/candidates/{id}/resume-pdf — Generate formatted A4 resume
      POST /api/admin/custom-columns    — Add custom candidate fields
      PUT  /api/settings/integrations   — Update Gmail settings
      POST /api/login                   — User authentication


   ------------------------------------------------------------------------
   8. FRONTEND — REACT AND UI FEATURES
   ------------------------------------------------------------------------

   The frontend is a React 18 Single Page Application (SPA) bundled by
   Vite. It communicates with the FastAPI backend via Axios HTTP calls.
   Styled with custom vanilla CSS with light and dark theme support.

   THE 8 APPLICATION PAGES:

   Page 1: Login / Register (/login)
      Login with Firebase Auth or native database authentication. Password
      validation requires at least one digit. New registrations enter a
      pending approval state until an admin approves the account.

   Page 2: Dashboard (/)
      Main candidate table showing all profiles. Supports filtering,
      sorting, status updates, formatted resume preview, and Excel export.
      Shows recruitment metrics and statistics via Recharts graphs.

   Page 3: Jobs (/jobs)
      Create and manage job descriptions. Upload JD documents to auto-fill
      form fields. Run AI matching. Select candidates for jobs. Share job
      postings with external client accounts.

   Page 4: Upload (/upload)
      Drag-and-drop area for uploading individual PDF or DOCX resumes. Also
      supports Excel (.xlsx) bulk import for uploading many candidates at once.
      Shows real-time processing status updates.

   Page 5: Chat (/chat)
      AI recruiter chatbot interface. Type questions in plain English. The
      system routes to SQL query (Route 2) or vector search (Route 3) or
      direct conversation (Route 1). Responses are rendered as rich markdown
      including tables and bullet points.

   Page 6: Admin (/admin)
      Restricted to Admin users. Manage user accounts, approve registration
      requests, add custom candidate fields, configure keyword masking, and
      update Gmail email integration settings.

   Page 7: Connect (/connect)
      Configure external integration settings including Gmail IMAP and SMTP
      credentials. Enable or disable the background email worker.

   Page 8: Templates (/templates)
      Resume template configuration. Preview A4 formatted resume layout and
      generate downloadable formatted resumes for selected candidates.

   NOTABLE UI FEATURES:

      Light / Dark Theme
      Toggle between light and dark mode. Preference stored in localStorage
      and applied via CSS custom properties on document.documentElement.

      Recruiter Persona Matrix
      Switch the active recruiter persona (Boopathi, Praveen, Harish, Sabari)
      from the header. All API calls automatically include the selected
      recruiter's name via the x-user-username request header. This alters
      database ownership scopes and filtering.

      Data Masking
      Sensitive fields like CTC and certifications are shown as [HIDDEN] for
      non-HR users. Keywords in the masked_keywords table (e.g., CSSA, LSA)
      are replaced with **** throughout the UI for non-admin users.

      Excel Export with Dropdown Validations
      Exported Excel files include built-in cell validation dropdowns (New,
      In-Review, Available, etc.) so external clients can update candidate
      statuses directly in the spreadsheet.

      Drag-and-Drop Upload
      Powered by react-dropzone. Accepts PDF, DOCX, and XLSX file types
      with visual feedback during drag-over and upload states.

      Recharts Metrics
      Dashboard shows recruitment statistics as interactive charts including
      candidates by status, experience distribution, and sourcing metrics.

      React Markdown
      Chat responses from the AI are rendered as rich formatted text with
      support for tables, bold text, bullet points, code blocks, and headers.

   10. SECURITY AND ACCESS CONTROL
   ------------------------------------------------------------------------

   Hire AI implements a 4-level role-based access control system:

   ROLE 1: Admin
      Has access to everything in the system. Can manage users, approve
      registrations, configure custom fields, set keyword masking rules,
      and update email integration settings. No information is hidden from
      the Admin role.

   ROLE 2: HR
      Can view all candidate fields and data. Can create jobs, run AI
      matching, export candidate data, and view all profiles. Cannot access
      user management or system configuration settings.

   ROLE 3: Recruiter
      Can upload resumes, search candidates, use the AI chat, and view
      jobs. Sensitive fields like CTC and salary information are masked.
      Certification keywords (CSSA, LSA) are hidden and replaced with ****.

   ROLE 4: External Client
      Can only view job postings that have been specifically shared with
      their account, along with the matched candidates for those jobs.
      Cannot see the general candidate database, contact details, or any
      salary information.

   ADDITIONAL SECURITY FEATURES:

      Per-User Field Hiding
      Admin can configure which specific database fields each user cannot
      see. Configuration stored in the users table as a comma-separated
      list of column names in the hidden_fields column.

      Keyword Masking
      Terms stored in the masked_keywords table are automatically replaced
      with **** throughout the UI for all non-admin and non-HR users. This
      prevents exposure of sensitive certification and client information.

      Change Request Approval Workflow
      Profile edits submitted by non-admin users are not applied immediately.
      They create a pending change_request record that an admin must review
      and approve or reject before changes take effect.

      Activity Audit Log
      Every significant action — login, file upload, status change, admin
      configuration change — is recorded in the activity_logs table with
      the username and exact timestamp.

      Account Approval Flow
      New user registrations are created with is_approved = 0. The account
      cannot be used until an admin explicitly approves it, preventing
      unauthorized access.

      Firebase Authentication (Optional)
      The system can optionally integrate with Google Firebase for OAuth-
      based login using Google accounts.

      AI extracts data consistently from every resume format. There are no

   4. PLAIN ENGLISH SEARCH
      No need to know SQL syntax or Excel filter logic. A recruiter can simply
      type: "Find me CSSA-certified Pega candidates with 8+ years experience

      as the candidate database grows.

      Admins have granular per-user field control. Full audit logs track every
      action for accountability and compliance.

      Share specific job postings and matched candidate profiles with external
      clients through controlled access without the risk of sharing entire
      spreadsheets or sensitive candidate databases.

   8. FULLY CUSTOMIZABLE FIELDS
      Admins can add new custom fields to the candidate database at any time.
      The AI automatically learns to extract those new fields from all future
      resumes without any code changes.

   9. INSTANT REPORTS AND EXPORTS
      One-click export to Excel with built-in status dropdowns. External
      clients can mark candidate statuses directly in the spreadsheet without
      needing system login access.

   10. ELIMINATES DUPLICATE WORK
      The system tracks every processed email by unique message ID. A
      candidate sending the same resume twice, or a forwarded email arriving
      twice, will not create duplicate records in the database.
